# Механизм переключения

1. Собственные настройки: `/data/data/wakeword/config.json`.
2. Реестр прошивки: `/data/quasar/data/spotter.json`, массив `models`.
   Подменяются все записи категории `spotter`, типа `activation/alisa`.
3. Источники встроенных моделей: `/system/vendor/quasar/spotter_models/activation/`.
   Оригиналы сохраняются в `/data/data/wakeword/models/builtin/`;
   оригиналы кэша — в `models/cache-originals/<UUID>` рядом с ними.
4. Перед изменением файлов создаются полные временные папки. После `q stop`
   каталоги заменяются целиком, затем выполняется `q start`.
5. Прошивка считает CRC32 содержимого всех файлов в порядке сортировки путей.
   В подменённую модель добавляется четырёхбайтовый `zz-wakeword-crc32`,
   обеспечивающий ожидаемую CRC32. Веса выбранной модели не меняются.
6. В `/system/vendor/quasar/quasar.cfg` для другого имени добавляется `activation`
   в `aliced.voiceDialogSettings.onlineSpotterValidationDisabledTypes`.
   Исходное состояние хранится в `/data/data/wakeword/validation-backup.json`.
   При возврате на Алису восстанавливается именно этот элемент настройки,
   без отката остальных пользовательских изменений.
7. После старта в течение 10 секунд проверяются процессы, пути, флаги и CRC32.
   Это не проверка фактической голосовой активации.

Серверный слот остаётся `alisa`, локаль не меняется. Бэкапы не удаляются при
возврате. Удаление пакета через менеджер не выполняет восстановление моделей:
перед удалением выполните `switch alisa` и дождитесь успеха.

Проверено на Mini 2; новая прошивка может изменить формат реестра или алгоритм
проверки. Новая серверная модель может создать новую папку, требующую `apply`.
