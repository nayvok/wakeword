# Участие в разработке

Первая публичная версия содержит переключение встроенных имён,
CLI, JSON API v1 и пакет YAM. Проверено на Мини 2 с часами. Новые слова и обучение — отдельные задачи roadmap.

## Локальная проверка

Нужны Rust **1.89+** с Clippy/rustfmt и Python **3.11+** для упаковки.

```sh
cargo fmt --all --check
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
```

Обычные тесты работают с временными файлами и не требуют колонки.
Не запускайте `apply`/`switch` на компьютере: это команды для файловой системы колонки.
Для проверки чтения/записи отдельного конфига можно задать `WAKEWORD_CONFIG`.
Эта переменная не перенаправляет пути моделей и прошивки.

## Сборка пакета

Из корня проекта на Linux/macOS с Rust, установленным через rustup:

```sh
rustup target add aarch64-unknown-linux-musl
cargo build --release --target aarch64-unknown-linux-musl
python3 scripts/package.py
```

Линковщик берётся из текущего Rust toolchain. Результат — `wakeword-cli.yap`.
Архив содержит только manifest и бинарник, без прошивки, моделей и логов.
Проверки CI собирают и проверяют пакет, но не подтверждают работу на реальном устройстве.

## Изменения и PR

- Для исправления опишите симптом, причину и проверку.
- Для изменения API добавьте контрактный тест и обновите `docs/API.md`.
- В пределах API v1 сохраняйте поля ответов, команды и смысл кодов ошибок.
  Новые поля допустимы; удаление или смена смысла требует новой версии API.
- Поддержку другой колонки заявляйте после проверки её путей, архитектуры,
  моделей, перезапуска и возврата к оригиналу. Приложите модель устройства,
  версию прошивки и результаты, без персональных данных.
- Не добавляйте токены, приватные ключи, сырые логи, бэкапы прошивки или веса Яндекса.
- Обновляйте `CHANGELOG.md` для пользовательских изменений.

На колонке проверьте переключение, голосовой ответ, обычный перезапуск и возврат
на Алису. Не запускайте второй `yam run` для этого пакета, пока первый не завершён:
YAM может отменить предыдущий процесс.
